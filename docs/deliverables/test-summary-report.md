## 1. はじめに

### 1.1 概要
照合キットの受け入れの確かめ（`test-cases.md` の TC-01 から TC-20）の結果。試験した commit・日時・Python の版は生成区画の先頭に出る。自動で流すケース（TC-01 から TC-17）は pytest の結果から、ブラウザで人が通すケース（TC-18 から TC-20）は「保留」として数える。試験者は、この道具を作った側（開発者本人）。試験の場所は、開発に使った 1 台の Windows の PC。

## 3. 詳しい結果
ケースごとの結果は上の表の「結果」の列。ケースの内容と、結ぶ pytest の試験の名前は `test-cases.md`。不合格のケースがあれば、その試験の名前が表の最後の列に出る。再現するには、表の名前をそのまま `pytest` に渡す（例：`.venv\Scripts\python -m pytest tests/test_changes.py::test_the_requester_cannot_approve_reject_or_apply_whatever_roles_he_has`）。

別の確かめの記録：コードを 36 か所わざと壊して試験が赤くなるかを見た結果は `docs/validation/mutations.md`。受け入れの確かめを本物のサーバーに対して通した記録は `docs/validation/acceptance.md`。

## 4. Variances（計画した試験と実際に行った試験の違い、試験の環境と運用の環境の違い）

### 4.1 計画と実際の違い
- 計画したケース 20 のうち、TC-18 から TC-20 はブラウザで人が通す物。2026-10-25 にスクリプトでヘッドレスの Microsoft Edge と HTTP を操作して通し、各ケースの「実施の記録」に書いた（`docs/validation/acceptance.md` にも要約）。人の目の確かめは別に行うので、この報告の数え方（人が通すケースは保留）に従って「保留」のまま数えてある。
- 照合の当たり外れ（適合率・再現率）は、正解付きの試験データ（Splink の金融取引の例）で数えた。そのデータは git に入っていないので pytest では流さず、一度だけ流した記録が `docs/validation/results.md` にある。TC-03 の pytest は、計算の式と、評価データの再現を確かめる物。
- 受け入れの手順で言う「画面を人が見る」確かめは、pytest では HTTP のクライアントを使って画面の HTML の文字を確かめている。見た目（色・配置）は確かめていない。

### 4.2 試験の環境と運用の環境の違い
- **sandbox と使い捨てのデータベース**。試験は、試験ごとのデータベースのファイルで行い、運用の本番のデータベースには触れない。変更の申請の試験（TC-12）も、本番の写しの上で行う。運用の本番では、本物の明細と、本物の承認の履歴がある。
- **パスワードの強さ**。試験ではパスワードの計算量を小さくして（運用の 2^17 に対し 2^10）速くしている。運用の値は `close_kit/config.py` にある（試験の中では使っていない）。
- **日付**。試験は日付を固定している（期日の試験など）。運用は今日の日付。
- **ネットワーク**。試験は外への通信をしない。運用も、この道具は外へ通信しない。サーバーが待つ宛先は `127.0.0.1` と `localhost` だけ。
- **ブラウザ**。pytest はブラウザを使わない。ブラウザでの見た目と操作は TC-18 から TC-20（スクリプトで通した記録はある。人の目の確かめは保留）。
- **SAP**。転記ファイルは SAP に取り込んで試していない。
- **Windows 以外**。Windows でだけ流した。
