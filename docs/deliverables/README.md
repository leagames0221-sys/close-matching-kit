## 受け入れの手順（見る人が、手順の中で見る物）

前提：Python が入った Windows の PC。README の手順で環境を整え、利用者を作る。

```
.venv\Scripts\python -m close_kit seed-demo
.venv\Scripts\python -m close_kit serve
```
`http://127.0.0.1:8765` を開く。パスワードは `var/demo_users.txt`（git には入らない）。

1. **見本のワークブックを本番へ上げる。** `demo-admin` で「ワークブック」から `samples/sample_workbook.xlsx` を読み込む（sandbox の版になる）。「変更の申請」→「申請を作る」→「申請する」。`demo-admin2` が「事前承認」（試験が自動で流れる）。`demo-approver` と `demo-admin2` が「結果を承認」。`demo-admin2` が「本番に適用」。`demo-admin` が「確認した」。本番の版が入る。`demo-admin` が自分の申請を承認しようとすると、拒否される。
2. **許容差を変える申請。** 本番に見本を取り込む（上の帯を「production」にして、「明細の取り込み」。まだ「照合」は実行しない）。見本のワークブックの「パスルール」シートの 1 行目（参照が同じ）の `amount_tolerance_minor` を 100 から 0 に、「承認ルート」シートの 10 万円（1 行目の上限と 2 行目の下限）を 20 万円に変えて保存し、読み込んで、同じ流れで申請する。事前承認の後の試験の結果に、区分ごとの件数の前と後と、区分が変わった行、承認の閾値の境目の承認できる人の前と後が並ぶ。この変更では、手数料の差 50 が自動の照合に入らなくなるので、見本の道筋が「理由コード R01 を付ける」で止まり、結果は「失敗（変更の影響）」と出る（結果の承認に進める）。
3. **本番で見本の道筋を流す。** 本番で照合・理由コード・仕訳の承認・調整項目の承認・11 月の取り込みを行うと、残高一致表の差が 0 になり、転記ファイルが出る。sandbox では転記ファイルが出ない。
4. **承認者の手順どおりに操作する。** [manual-users.md](manual-users.md) の「仕訳を承認する」のとおりに操作すると、書いてある画面の名前・ボタン・結果が実物と同じ。

スクリプトで通した記録は `docs/validation/acceptance.md`。

## 作らない物
急ぎの変更の別の流れ、変更管理の会議の議事、申請の項目の人員・つなぎ目の問題・他のアプリの変更・費用、環境の間のデータの写し、シングルサインオン、バックアップの道具、OS の利用者によるデータベースのファイルの直接の書き換えの防止。理由は `docs/adr/0005-what-is-not-built.md` と `docs/adr/0008-change-requests.md`。
