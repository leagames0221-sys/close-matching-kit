# 公開資料の機能との対応表

様式の出典：表の形（機能・作った／作らない・理由の 3 列）は作者の設計判断（手本は見つからなかった。`docs/sources.md`）（行の元は、BlackLine Inc. が公開している資料の機能の一覧。事実の引用だけで、文は写していない）。この repo に合わせて章を変えた。

**この表の決まり**
- 「同じ製品」とは言わない。BlackLine は BlackLine Inc. の製品名で、この道具は同社と関係が無い。公開資料に書いてある機能の語を、行の見出しにしただけで、その機能がどう動くかは公開資料に書かれていない所が多い。
- 照合の当たり外れは、**正解付きの試験データ**（Splink の金融取引の例）で数えた物（`docs/validation/results.md`）。BlackLine の出力と比べた数字ではないので、比べたとは書かない。
- 処理量は、手元の PC での実測だけを書く（`docs/validation/results.md` の「44,868 行の照合に 0.6 秒」）。BlackLine の宣伝の数字とは比べない。
- 照合 PDF の 7 つの区分は、名前だけで挙げる（Match・Create Item・MyViews・Reason Codes・Filter & Search・Role Assignments・Data Sources）。PDF の画面の写真の赤い数字と名前の結び付きは、位置から読むしかなく確かめきれなかったので、番号は付けない。
- 値段：公式の定価は公開されていない。Vendr の頁の本文は「Median buyer pays $40,125 per year」「Based on data from 74 purchases」と書き、**74 件の購入の年額の中央値**。この数は頁の本文の値で、同じ頁の上の見出しは「$40,125 Avg Contract Value」「59 Deals handled」と、名前も件数も違う。同じ頁は、値段がモジュール・取引量・会社の数・導入の複雑さで大きく変わると書くが、74 件がどのモジュールを買ったかは書いていない。この道具の 3 つの芯だけの値段ではないし、この道具の値段との比べでもない。この道具は 1 台の PC で動き、有料の部品は無い。（出典：Vendr, BlackLine pricing https://www.vendr.com/marketplace/blackline ）

出典の略称：[作業管理 PDF] https://pages.blackline.com/rs/blacklinesystems/images/Task%20Management.pdf 、[照合 PDF] https://pages.blackline.com/rs/blacklinesystems/images/BlackLine-Transaction-Matching-Module-Overview.pdf 、[仕訳 PDF] https://pages.blackline.com/rs/blacklinesystems/images/Journal%20Entry.pdf 、[仕訳の製品頁] https://www.blackline.com/products/financial-close/journals/ 、[買い手の手引き] http://pages.blackline.com/rs/blacklinesystems/images/BLBuyersGuide.pdf

## 1. 作業管理（Task Management）

| 公開資料の機能 | 作った／作らない | この道具での形・理由 |
|---|---|---|
| 繰り返しの決算の作業を、期間ごとに自動で予定する [作業管理 PDF] | 一部 | 管理者が「この期間の作業を作る」を押すと、月次の繰り返しの作業が期間ごとにできる。自動の予約（押さなくても作られる）は作らない |
| 依存関係で、作業が正しい順に終わる [作業管理 PDF] | 作った（強さは弱い） | 前の作業が完了するまで、次を「作成完了」にできない。「始められなくする」所までは作らない（`docs/adr/0007`） |
| 所要時間を測って、予定と実績を比べる [作業管理 PDF] | 作らない | 期日と完了の記録はあるが、作業にかかった時間を測る機能は作らない。作る範囲を広げないため |
| 役割ごとの承認の流れと、操作の記録 [作業管理 PDF] | 作った | 作業ごとに作成者と確認者を決め、別の人が完了にする。誰が・いつ・何をを操作の記録に残す |
| 複数の休日のカレンダーと複数のタイムゾーン [作業管理 PDF] | 一部 | 国の祝日表（内閣府の CSV）と、会社の休日の 1 枚。複数のカレンダーとタイムゾーンは作らない（日本の 1 社の見本のため） |
| 営業日・暦日・平日、設定できる期間で決算を組む [作業管理 PDF] | 作った | 期日は期末日からの日数（営業日・暦日・平日。0 日目は期末日。数え方は Oracle の Close Manager の Day Zero に合わせた。`qa-log.md` Q-04）。期間はワークブックの「会計期間」 |

## 2. 取引の照合（Transaction Matching）

| 公開資料の機能 | 作った／作らない | この道具での形・理由 |
|---|---|---|
| 業務の側が持つルールで動く照合 [照合 PDF] | 作った | ワークブックの「パスルール」。上から順に当てる |
| 1 対 1・多対 1・多対多の照合 [照合 PDF] | 作った | 1 対 1、束ねる（多対 1・1 対多・多対多）。束は金額の許容差を使わず、日付は勘定日が束ねるキーの時だけ比べる（Oracle に合わせた）。同じ参照の行（重複）も照合に入り、印が付く。相手が複数ありうる時は自動にせず候補にする |
| 自動の照合と、候補を出す照合 [照合 PDF] | 作った | 区分「自動」と「候補」。候補は人が確かめる |
| 例外の処理に、メールの通知と役割の流れ [照合 PDF] | 一部 | 役割の流れ（手の照合を別の人が承認）は作った。メールの通知は作らない（外への通信をしない方針） |
| 取り込みの道具で、検索・連結・分解・加工を自動で [照合 PDF] | 作らない | 取り込みは、データ源ごとの形式（全銀・camt.052・CSV）と、列の対応だけ |
| 編集できるどんな形式・データ源からも自動で取り込む [照合 PDF] | 一部 | 全銀（固定長）・camt.052（XML）・CSV。PDF の明細や API からの取り込みは作らない |
| 利用者が決めた論理で、調整項目と調整仕訳を一括で作る [照合 PDF] | 一部 | 理由コードで、グループか行ごとに 1 件ずつ作る。一括は作らない。許容差の中の差額は、規則の「差額の相手勘定」があれば、照合を実行した時に道具が仕訳の下書きを作る（作者の判断。Oracle は許容差の中の差額を external transaction として自動で作り、Odoo は不足払いのモデルで差額を counterpart entries の勘定で消すと書くが、どちらも仕訳の下書きは書かない。承認は別の人。`docs/adr/0003` D6） |
| 7 区分の 1 つ：Data Sources（データ源。1 つから上限なしの組み合わせ、データ源の絞り込み）[照合 PDF] | 一部 | データ源は照合セットごとに 2 つまで。絞り込みは作らない |
| 7 区分の 1 つ：Match（利用者が手で照合できる。手の照合は、承認の流れの対象に「できる」＝任意）[照合 PDF] | 作った（違いは意図したもの） | 手の照合はある。その承認は**必須**で、別の人が承認する（`qa-log.md` Q-06） |
| 7 区分の 1 つ：Role Assignments（標準の承認の流れで、件数の多い照合の統制を保つ）[照合 PDF] | 作った | 役割（作成者・承認者・管理者・監査人）と、手の照合・仕訳・調整項目の別の人の承認 |
| 7 区分の 1 つ：Create Item（必要な調整や時期のずれを作る）[照合 PDF] | 作った | 調整項目。承認が要る |
| 7 区分の 1 つ：MyViews（自分用の表示の保存）[照合 PDF] | 作らない | 利用者ごとの設定を持たない |
| 7 区分の 1 つ：Filter & Search（絞り込みと検索）[照合 PDF] | 一部 | 区分・状態・種類での絞り込みだけ。自由な検索は作らない |
| 7 区分の 1 つ：Reason Codes（利用者が決める理由コード）[照合 PDF] | 作った | ワークブックの「理由コード」。仕訳か調整項目に結び付く |

## 3. 仕訳（Journal Entry）

| 公開資料の機能 | 作った／作らない | この道具での形・理由 |
|---|---|---|
| 仕訳の型ごとに設定できる雛形 [仕訳 PDF] | 一部 | 手入力と CSV の取り込みの 2 つの入口。型ごとの雛形は作らない |
| 検証規則で、転記の失敗をなくす。規則は GL から取れる [仕訳 PDF] | 一部 | 検証規則 5 つ（借方＝貸方、明細数、勘定コード、締めた期間、摘要）を、保存・申請・承認の 3 回かける。GL からの取得は作らない |
| 裏付けの文書を、どんな形式でも添付して保存する [仕訳 PDF] | 作らない | 添付を持たない |
| 自動で転記し、GL から文書番号を取り戻す [仕訳 PDF] | 作らない | 転記ファイルを出すだけ。SAP の取り込みの試験はしていない（`qa-log.md` Q-03） |
| 動的な流れで、仕訳を承認すべき人へ回す [仕訳 PDF] | 作った | 承認ルート（金額の幅ごとの承認できる人）。作った本人は承認できない |
| 金額の閾値に基づく承認の流れ [仕訳 PDF] | 作った | 同上。閾値の境目で承認できる人が変わる |
| 複数のシステムへ自動で転記する [仕訳 PDF] | 作らない | 1 つの形（SAP の一般仕訳のアップロードの項目の技術名）のファイルだけ |
| 40 を超える ERP と財務システムからの転記を 1 つの場所で見て管理する（"more than 40 ERP and financial systems"）[仕訳の製品頁] | 作らない | ERP と繋がらない。ファイルで出し入れする（`docs/adr/0005`） |
| 監査人は読むだけ [仕訳の製品頁・仕訳 PDF の資料の範囲] | 作った | 役割「監査人」。すべての画面を見られ、変える操作はサーバーが断る |

## 4. その他
